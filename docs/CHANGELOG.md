# 버전별 변경 내용

번호는 저장소 루트의 `VERSION`을 따릅니다. 태그는 `v0.9.0`과 `v1.0.0`에 붙어 있습니다. 왜 그렇게 만들었는지는 [설계](DESIGN.md)에, 버전마다 무엇을 어떻게 확인했는지는 [점검 기록](REVIEW-2026-11-10.md)에 있습니다. 쓰는 법은 [README](../README.ko.md)에 있습니다.

## 1.1.0 (2026-11-25): 설정창 · 화면 영어 · 실험실

1.0.1 위에 올린 버전입니다(2026-11-26에 합침). 1.0.1이 고친 것이 모두 들어 있고, 1.0.1이 새로 하는 말에도 영어를 넣었습니다: `doctor`의 "MCP for Unity 서버가 맡은 창만 봄" 항목과 그 안내, Unity 하위 세션 지침의 6번(영어판에도 같은 줄), Claude Hand Tools가 꺼진 연결을 다시 켜며 Console에 남기는 줄.

설정이 `config.json`과 명령에만 있어서 무엇을 켜고 끌 수 있는지 보이지 않았고, 화면의 글이 전부 한국어라 영어 README를 보고 온 사람은 버튼의 뜻을 표에서 찾아 읽어야 했습니다. 셋을 한 묶음으로 넣었습니다.

- **설정창.** Unity 채팅창과 Blender 패널에 톱니바퀴 버튼이 생겼고, 누르면 설정창이 뜹니다. 탭은 "기능 켜고 끄기"와 "실험실" 둘입니다. 채팅창 둘레에 칸을 더 늘리지 않으려고, 접는 칸이 아니라 따로 뜨는 창으로 했습니다.
  - 켜고 끄는 것: 요청마다 든 시간 · 토큰 줄, 바뀐 다른 창의 그림 붙이기(새 스위치), 답이 오면 작업 표시줄 깜빡임(새 스위치), Claude 데스크톱 앱에서 보기, Claude Hand 창 자동 최소화.
  - 날수: **대화 내용 보관 일수**(새로 생겼습니다. 채팅창에 다시 보여 주는 지난 대화와 그 그림을 며칠 둘지이고, 기본 0은 날짜로는 지우지 않는다는 뜻입니다), 옮긴 파일 보관 일수(전부터 있던 `exchange_keep_days`).
  - 기본값은 모두 지금까지의 동작입니다. 안전장치 · 보호 규칙 · 되돌리기 지점은 설정이 아니고 끌 수 없습니다.
  - 명령: `uv run tools/claude_hand.py settings`(목록과 지금 값), `settings <이름> <값>`, `settings lab <기능> on|off`. 예전의 `remote-control` · `minimize` · `clean-exchange --keep-days`도 그대로 됩니다.
- **바꾸면 바로.** 설정은 전처럼 `config.json`에 있고, 쓰는 쪽(채널, 명령, 안전장치, 두 패널)이 쓸 때마다 파일이 바뀌었는지 보고 다시 읽습니다. 그래서 Claude Hand를 다시 켜지 않아도 됩니다. 다시 켜야 하는 것은 넷이고 설정창에 `*`로 표시됩니다: 데스크톱 앱에서 보기(Claude Code의 시작 인자입니다), 창 자동 최소화(세션이 처음 일할 때 한 번 하는 동작입니다), 보관 일수 둘(켤 때 정리합니다).
- **화면 영어.** 설정창의 **언어 · Language**에서 English를 고르면 두 패널의 글, 채널이 채팅창에 쓰는 줄, 명령 출력과 진단, 안전장치 · 보호 규칙 · 감독 훅이 호출을 막으며 하는 말이 영어로 나옵니다.
  - 한국어 글은 코드에 그대로 두고 `T("…")`로 감쌌고, 영어는 구현마다 표 하나에 있습니다(Python 도구 458개, 안전장치 13개, Blender 애드온 227개, Unity 패키지 145개). 한국어일 때는 원문이 그대로 나가므로 글이 달라지지 않습니다.
  - 수를 세는 글은 하나일 때의 영어를 따로 둡니다(`1 action`, `1 rule`, `1 day`). 한국어는 수에 따라 글이 달라지지 않아 원문이 하나뿐이라, 표 옆에 "하나일 때의 글" 표를 하나 더 두었습니다.
  - Blender의 패널 · 버튼 이름은 등록할 때 정해져서, 언어가 바뀌면 애드온이 클래스를 다시 등록합니다(1밀리초쯤). Unity 채팅창은 그릴 때마다 글을 다시 묻습니다.
  - 켜져 있는 감독에게는 채널이 "화면 언어가 바뀌었다"는 알림과 버튼 이름 대조표를 보내고, 하위 세션 정의와 감독 스킬을 그 자리에서 다시 씁니다.
  - 코드가 다시 읽는 글은 두 언어를 다 읽습니다. 맡기는 글의 `[요청 <번호>]`는 `[request <id>]`로 적어도 되고, 막힌 글에서 채팅창 줄을 만드는 곳은 그 글이 적힌 언어로 읽습니다.
  - `start-supervisor`가 uv나 claude가 없을 때 내는 두 줄도 설정의 언어를 따릅니다.
- **지침은 한국어 그대로.** Claude에게 주는 지침은 실제 감독 세션으로 다듬어 온 글이라 바꾸지 않았습니다. 화면이 영어일 때는 지침 끝에 "화면 언어: English" 절이 붙어, 지침이 한국어로 부르는 버튼과 막힌 글이 화면에서 무엇인지 알려 줍니다. 대조표의 영어는 화면이 쓰는 표에서 가져오고, 둘이 어긋나면 테스트가 실패합니다. `/agents`에 보이는 하위 세션 설명과 스킬 설명은 화면 언어를 따릅니다.
- **실험실.** 새 기능이 먼저 들어오는 자리입니다. 설정과 실험실 기능의 목록은 `settings/catalog.json` 한 파일이고(이름 · 설명 · 들어온 버전 · 기본값 · 언제 적용되는지), Python · Unity · Blender가 같은 파일을 읽어 줄을 그립니다. 실험실 기능은 꺼진 채로 들어오고, 기본 기능으로 올릴 때는 그 줄의 `stage`를 `stable`로 바꿉니다.
  - 첫 기능은 **Claude 지침 영어판**입니다. 언어가 English일 때 지침도 영어판(`prompts/en/`, `skills/orchestrator/SKILL.en.md`)으로 줍니다. 한국어판을 줄마다 옮긴 것이고(테스트가 줄 수 · 자리 표시 · 코드 조각을 견줍니다) 실제 작업으로는 이제 막 다듬기 시작해서 실험실에 두었습니다(아래 "실제 감독 세션으로 보며 찾아 고친 것").
- 함께 고친 것: Blender에서 보호 규칙을 연달아 바꿀 때(보기만을 더했다가 바로 풀기처럼 파일 크기가 같은 변경) 파일의 시각이 같으면 패널이 바뀐 것을 못 볼 수 있었습니다. 쓰고 나면 다시 읽게 했습니다.
- **열린 창으로 보며 찾아 고친 것.**
  - Unity 채팅창을 연 채 스크립트가 다시 읽히면(또는 Unity를 다시 열면) "나 (Claude Hand가 켜지면 보냅니다)"가 빈 채로 뜨고 보내기 버튼이 눌리지 않았습니다. Unity가 비어 있던 글 칸을 빈 글로 되살려서, 보내려고 둔 메시지가 있는 것으로 읽혔습니다. 1.0.0에도 있던 것입니다.
  - 영어에서 잘리던 글: 두 설정창의 긴 이름과 Blender 설정창의 언어 줄, Unity 보호 칸의 버튼 넷(창이 좁으면 두 줄로 나눕니다), "보내지 않고 지우기" · "풀기" 버튼, Blender 보호 칸의 "이번만" 체크박스(괄호 부분을 아래 줄로). 두 설정창은 지금 언어의 가장 긴 이름에 맞춰 넓어집니다.
  - 언어를 바꾼 뒤에도 옛 언어로 남던 줄: Blender 패널의 "담당: …" 줄과 두 패널의 "다른 창" 줄. 언어가 바뀌면 다시 말합니다.
  - 채널을 다른 agents 폴더로 띄우면(테스트, 시험) 감독 스킬은 실제 `~/.claude/skills`의 것을 다시 쓰던 것. agents 폴더 옆의 `skills`를 봅니다.
- **실제 감독 세션으로 보며 찾아 고친 것 (2026-11-26).**
  - 지침 영어판에서 감독이 시키지 않은 씬 저장을 Unity 담당에게 맡겼습니다("Save the scene"). 이름 없는 씬이 새 파일로 저장됐고, 저장은 되돌리기로 돌아오지 않습니다. 한국어판에서는 같은 요청에 "Don't save the scene"이라고 맡깁니다. 두 판 모두 저장에 대한 규칙은 옮기기 순서 안에만 있어서, 영어 채팅 규칙의 "맡길 때" 줄에 한 문장을 더했습니다(사용자가 시킨 것만 맡긴다, 저장은 사용자가 원할 때만, 결과에 저장되지 않았다고 알린다). 창 없이 감독만 따로 돌려(맡기는 호출은 훅이 막아 Unity · Blender는 건드리지 않음) 재 봤습니다: 더하기 전 5번 중 5번 저장을 맡김, 더한 뒤 5번 중 0번, 한국어판 4번 중 0번.
  - "Claude 데스크톱 앱에서 보기"를 끄고 켜면 Claude Hand 창의 제목이 `claude`였습니다. 세션 이름을 Remote Control과 함께만 주고 있었습니다(1.0.0부터). 이제 늘 `--name "Claude Hand"`를 줍니다.
  - 자동 최소화를 꺼도 `start`의 안내와 Claude Hand 창의 첫머리가 "저절로 최소화됩니다"라고 했습니다.
  - `CLAUDE_HAND_LANG=en`으로 `doctor`를 한 번만 영어로 보면 설치된 하위 세션 정의와 스킬을 "이전 버전으로 만든 것"이라고 했습니다. 파일은 설정의 언어로 쓰여 있으니, 견줄 때는 그 언어로 봅니다.
  - `settings` 목록에서 `never removed` 줄의 칸이 밀리던 것, 언어 알림의 "한국어(으)로".

확인한 것: Python 테스트 559개(1.0.1의 14개 포함), 창 없는 Blender 안 테스트 120개(새 7개: 설정창의 줄, 바꾼 것이 파일에 적히는지, 언어를 바꾸면 패널 · 버튼 이름이 따라오는지), 창 없는 Unity 6.3 안 자가 테스트 79개(새 7개: 언어가 설정을 따라 그 자리에서 바뀌는지, 영어가 없는 글은 한국어로 나오는지, 설정이 파일에 적히고 다른 창이 바꾼 것을 읽는지, 쓰다 만 파일이면 직전 설정을 쓰는지, 설정창의 줄이 목록에서 오는지. `hand_test`의 사본을 창 없이 열어 돌렸습니다). 만들기 전에 실험한 것: 켜진 프로세스가 바뀐 설정 파일을 다시 읽는 것(바뀌지 않았을 때 확인 한 번에 17 µs, 쓰다 만 파일이면 직전 설정을 씀), 켜진 Blender에서 패널 · 버튼 이름을 다시 등록하는 것(1.3 ms).

열린 창으로 본 것: 실제 `hand_test`와 실제 설정 폴더를 건드리지 않게 시험 환경을 따로 꾸몄습니다(`hand_test`의 사본을 연 Unity, 저장소의 애드온을 올려 띄운 Blender, 임시 설정 폴더). 두 설정창과 채팅창을 그림으로 떠서 보고 버튼을 눌렀고, 채널은 실제 것을 띄워 감독 자리에만 흉내를 세웠으며, 감독 훅과 가드 훅은 Claude Code가 부르는 방식 그대로 돌렸습니다. 항목별 결과는 [검증 순서](TEST-PLAN.md) 34단계에 있습니다.

실제 감독 세션으로 본 것(2026-11-26): 실제 `hand_test`와 `test_blender`를 열고 Claude Hand를 새 대화로 두 번 켰습니다. 한국어 요청 한 바퀴, 켜진 채 언어 바꾸기, 영어 요청과 답, 버튼을 화면의 이름(`Undo`, `Release`)으로 부르는지, 두 창을 함께 되돌리기, 실험실의 지침 영어판으로 한 바퀴, 다음에 켤 때 적용되는 설정 둘, 한국어로 되돌렸을 때 정의 파일이 전과 같은지를 봤습니다. 항목별 결과는 [검증 순서](TEST-PLAN.md) 34단계에 있습니다.

아직 보지 않은 것: "데스크톱 앱에서 보기"를 껐을 때 앱의 세션 목록에서 빠지는지(명령줄에 `--remote-control`이 없는 것까지 봤습니다), 작업 표시줄 깜빡임, 설정창 줄에 마우스를 올리면 뜨는 설명, Unity 설정창의 언어 목록을 직접 누르는 것.

## 1.0.1 (2026-11-25): 하위 세션이 다른 Unity 창을 건드리던 것, 연결이 끊기던 것

Unity 창을 둘 이상 열어 두고 쓰는 사용자 테스트에서 "하위 세션이 MCP를 제대로 못 찾고 다른 Unity 창을 침범하는 일이 하루에 다섯 번", 그때 "Window > MCP for Unity가 Connected가 아닌 창이 있었다"는 보고가 왔습니다. 원인은 claude-hand가 기대던 MCP for Unity(서버 · 패키지 10.3.0, Stdio)의 동작 셋과 claude-hand 자신의 동작 하나였습니다.

**왜 다른 창으로 갔나.**

- `--default-instance`는 기본값일 뿐입니다. 맡은 창이 서버의 목록에서 잠깐 빠지면 서버가 다른 창을 고릅니다. 호출마다 도는 미들웨어가 "보이는 창이 하나뿐이면 그 창"을 골라 세션에 남기고(그래서 맡은 창이 돌아와도 계속 다른 창으로 감), 보내다 실패한 명령은 응답하는 아무 창의 포트로 다시 보냅니다. 목록에서 빠지는 때: 창의 MCP for Unity 연결이 꺼졌을 때(보고된 "Connected가 아님"), 스크립트 다시 읽기가 마지막 신호에서 60초를 넘겼을 때, 0.3초 안에 답하지 못했을 때, 명령이 가는 도중에 다시 읽기가 시작됐을 때.
- 포트는 창의 신분증이 아닙니다. Unity 쪽은 다시 읽은 뒤 자기 포트를 3초 안에 다시 못 잡으면 6400부터 비어 있는 가장 낮은 포트로 옮깁니다. 그 포트가 방금까지 다른 창의 것이었을 수 있고, 서버는 기억하던 포트에 다시 붙으면서 상대가 누구인지 묻지 않습니다. 이 PC에서 창 하나만 쓴 하루치 Unity 로그에도 "포트를 다시 못 잡음"이 22번, "다른 포트로 옮김"이 3번 있었습니다.

**왜 끊겼나.**

- Unity 쪽 연결은 새 연결이 들어오면 기존 연결을 모두 닫습니다("only ever one active Python server"). 그런데 서버는 창을 찾을 때마다 모든 창의 포트에 붙어 봅니다. 창이 둘이면 두 하위 세션의 서버가 서로의 연결을 계속 끊고, 가던 명령은 끊겨서 다시 보내집니다(같은 로그의 "Suppressed duplicate command resent" 5번).
- claude-hand도 창 목록을 볼 때(`sync`, `list`, `doctor`, 채팅 채널의 자동 새로 고침) 그 포트에 붙어 봤습니다. 일하던 하위 세션의 연결을 claude-hand가 끊고 있었습니다.
- 연결이 한 번 꺼지면 Unity가 옛 포트를 놓지 않습니다. 연결을 끈 뒤에 보니 Unity 프로세스가 옛 포트(6400)를 계속 듣고 있었습니다(받아 주는 쪽은 없어서, 붙은 연결들이 쌓이기만 함). 그래서 다시 켤 때 "not released yet"가 이어지다 6401로 옮겼습니다. Unity를 닫자 풀렸습니다. 왜 놓지 않는지(Unity의 자식 프로세스가 소켓을 물려받는지, 닫기가 미뤄지는지)는 가리지 못했습니다. 옛 포트에 붙은 쪽은 연결은 되는데 답을 못 받습니다. MCP for Unity는 다시 읽은 뒤 여섯 번(약 49초) 다시 켜 보고 포기하고, 그러면 연결이 꺼진 채로 남습니다.

**고친 것.**

- 각 Unity 하위 세션의 서버에 고정 장치를 겁니다(`tools/unity_pin/sitecustomize.py`: `sync`가 정의 파일의 서버 환경에 `PYTHONPATH`와 `CLAUDE_HAND_UNITY_PIN=<Name@hash>`를 적고, Python이 시작하며 읽습니다. 서버의 코드는 건드리지 않습니다).
  - 맡은 창만 봅니다. 서버에게 다른 창은 없는 것과 같아서 고를 것이 없습니다.
  - 다른 창의 포트에는 연결하지 않습니다. 자기 창에도 연결을 쥐고 있는 동안에는 또 붙지 않습니다. 남의 연결도, 자기가 보내던 명령도 끊지 않습니다.
  - 새 연결은 그 너머의 창에게 어느 프로젝트인지 물어(`get_project_info`) 맡은 프로젝트일 때만 씁니다. 포트를 다른 창이 가져갔으면 그 연결을 버리고, 제 창이 옮겨 간 포트를 다시 찾아갑니다.
- claude-hand의 창 찾기는 포트에 붙지 않습니다. Unity가 0.5초마다 다시 쓰는 상태 파일이 15초 안에 쓰였는지로 봅니다(`discovery.listening`).
- 맡은 창이 응답하지 않으면 호출은 `No Unity Editor instances found` · `Could not connect to Unity`로 실패합니다. 하위 세션은 몇 초 뒤 다시 해 보고, 계속 그러면 그대로 보고합니다(지침에 넣음).
- `doctor`에 "MCP for Unity 서버가 맡은 창만 봄" 항목이 생겼습니다. 등록된 명령으로 서버를 띄우되 장치가 걸렸는지만 묻고 끝냅니다(Unity에 연결하지 않음).
- 꺼진 연결은 Claude Hand Tools가 다시 켭니다(`ChMcpLink`). MCP for Unity의 연결이 기다릴 것 없이(컴파일 · 가져오기 중이 아님) 20초 넘게 꺼져 있으면, MCP for Unity가 스스로 켜는 그 길로 다시 켜고 Console에 한 줄 남깁니다. `ch_editor_status`가 `mcp_for_unity`(켜짐 · 포트)를 알려 줍니다. 끄려면 EditorPrefs `ClaudeHand.KeepMcpForUnity`를 false로 둡니다.
- 받는 법: `update`(또는 `sync`)로 하위 세션 정의를 다시 쓰고 Claude Hand를 다시 켭니다. 다시 켜기는 프로젝트의 Claude Hand Tools가 1.0.1이어야 됩니다.

**확인.** Python 테스트 508개 통과(새 14개). 그 가운데 하나는 설치된 MCP for Unity 서버의 실제 코드를 가짜 창 둘 앞에서 돌립니다: 그대로 두면 "연결이 꺼짐 · 1분 넘게 다시 읽기 · 명령 도중 다시 읽기 · 포트를 다른 창이 가져감"에서 다른 창으로 가고, 장치를 걸면 한 번도 가지 않으며 창이 돌아오면 제 창으로 갑니다(포트가 서로 뒤바뀐 경우 포함). 하위 세션 정의가 띄우는 그대로 실제 서버 프로세스를 띄워 MCP로 호출해 본 것도 같았습니다. 실제 hand_test 창으로도 봤습니다(2026-11-25, 고친 패키지를 보게 하고 열어서): 고정한 서버의 호출이 통과했고(새 연결에서 창에게 프로젝트를 묻는 단계가 실제 Unity에서 통함), 창 안에서 연결을 끄자 호출이 `Could not connect to Unity`로 실패했고, 26초 뒤 아무도 누르지 않았는데 다시 켜졌으며(Console: `MCP for Unity의 연결이 24초 동안 꺼져 있어 다시 켰습니다 (포트 6401)`), 포트가 6400에서 6401로 옮겨 갔는데도 같은 서버의 다음 호출이 통과했습니다. Unity 패키지는 창 없이 컴파일해 본 뒤 그 창에서 돌렸고, Unity 안 자가 테스트는 다시 돌리지 않았습니다.

**아직.**

- Unity 창 둘을 함께 열고 감독 세션으로 보는 것은 하지 않았습니다([검증 순서](TEST-PLAN.md) 33단계). 창 하나로 본 것은 위와 같습니다.

## 0.18.0 (2026-11-24): 창마다 보호 규칙

"건드리지 마"를 기계가 지키게 했습니다. 메모는 Claude가 읽고 지키려고 할 뿐이고 가드는 남의 창만 막아서, 자기 창 안에서 보호해야 할 것을 건드리는 것은 막을 길이 없었습니다.

- **규칙 넷**: 창 전체(보기만 · 잠금), Unity 에셋 경로, 오브젝트(Blender는 컬렉션도), 금지 동작(씬 저장 · 에셋 삭제 · 플레이 모드 · .blend 저장). 두 패널의 **보호** 칸에서 더하고 풉니다. "이번만"과 "계속" 두 가지 수명이 있습니다.
- **말로 하면 제안이 됩니다.** "Hero는 건드리지 마"라고 하면 채팅창에 규칙 제안이 뜨고, **[추가]**를 눌러야 규칙이 됩니다. 푸는 것은 패널의 **[풀기]**뿐입니다.
- **막는 자리 셋.** 훅이 호출을 실행 전에 규칙과 견주어 막고, Unity가 보호 에셋의 저장 · 삭제 · 이동을 직접 거부하고, 그래도 바뀐 것은 호출 직후에 알아채 그 요청이 그 창에 한 일을 통째로 되돌립니다. 잠긴 창에는 감독이 일을 맡기지 못합니다.
- 채팅창에 `보호 규칙이 막았어요: …` / `보호된 … 이(가) 바뀌어 이 요청이 이 창에 한 일을 되돌렸어요`가 뜨고, `trace`에 `막음 (보호 규칙)`으로 남습니다.
- 하위 세션의 훅에 호출 뒤에 도는 것(PostToolUse)이 하나 더 생겼습니다. `uv run tools/claude_hand.py update`가 하위 세션 정의를 다시 씁니다.

쓰는 법은 위 [건드리면 안 되는 것 정해 두기](../README.ko.md#건드리면-안-되는-것-정해-두기-보호-규칙)에, 어디까지 보장되고 어디가 한계인지는 [설계](DESIGN.md)의 "창마다 보호 규칙"에 있습니다. 설계 때 "아직 안 해 봤다"고 한 셋(Unity가 거부 값을 받으면 정말 막히는지, Blender에서 바뀐 것을 알아채 되돌리기, 플레이 모드 취소)은 만들기 전에 실험했고, 그 결과로 Blender는 알림 대신 호출 앞뒤의 지문을 견주게 했습니다.

## 0.17.1 (2026-11-24): 열린 창에서 더 찾은 셋

0.17.0을 올린 뒤 열린 창과 실제 감독 세션으로 다시 보면서 고친 것입니다. 새 기능은 없습니다.

- **보내기만 한 요청의 되돌리기 버튼이 "이 창 +"라고 했습니다.** Blender에서 고치지 않고 Unity로 보내기만 했는데도 Blender 채팅창의 버튼이 "(이 창 + hand_test (Unity))"였습니다. Blender에는 되돌릴 것이 없는데 지점이 찍혔기 때문입니다. 이제 내보내기(`claude_hand_chat.export_fbx`)만 하고 나머지는 읽기만 하는 코드는 Blender를 바꾼 것으로 치지 않아, 버튼이 "(hand_test (Unity))"로 뜨고 누르면 Unity의 모델만 빠집니다. 처음에는 내보내기 한 줄만 있는 코드만 알아보게 고쳤는데, 실제 하위 세션은 내보낸 뒤 상태를 한 번 더 읽는 코드를 써서 그대로였습니다. 그래서 코드를 읽는 쪽(`handlib/looks.py`)이 내보내기를 알게 했습니다.
- **데스크톱 앱에서 `blender-open` · `unity-open`으로 연 창도 앱의 컨테이너 안에서 돌았습니다.** 0.17.0에서 `start`만 고쳤던 것과 같은 문제입니다(그렇게 연 Blender · Unity와 그 창이 띄우는 것들이 AppData를 앱 전용 사본으로 봅니다). 이제 그런 자리에서 부르면 탐색기를 거쳐 띄웁니다. 데스크톱 앱 세션에서 띄운 프로그램이 진짜 AppData를 보는 것과, 따옴표 · `&` · `%`가 든 인자가 그대로 가는 것을 확인했습니다.
- **감독의 대화가 압축된 뒤 첫 요청이 45초 늦게 갔습니다.** Claude Code가 긴 대화를 압축하며 남기는 요약 줄을 "누가 보낸 메시지"로 읽어서, 감독이 쉬고 있는데도 차례 중이라고 보고 다음 요청을 가장 긴 시간(45초)만큼 쥐고 있었습니다. 압축 두 시간 뒤에 보낸 요청에서 찾았습니다. 요약 줄은 이제 차례의 시작으로 치지 않습니다(요청마다 토큰을 나누는 쪽도 같은 줄을 읽으므로, 차례 중간에 압축돼도 그 뒤의 토큰이 같은 요청 몫으로 남습니다).

28단계 B는 고친 뒤 실제 감독 세션으로 다시 확인했습니다. 압축 뒤의 기다림은 자동 테스트로만 확인했습니다(켜져 있는 Claude Hand는 다시 켜야 새 코드를 씁니다).

## 0.17.0 (2026-11-24): Blender에서 보낸 모델이 깔끔하게 들어오게

Blender에서 보낸 모델이 Unity에 회색으로 들어오고, 부품마다 X 270° 회전이 붙고, 물리로만 움직이는 것은 멈춘 채로 왔습니다. FBX로 보내는 방식은 그대로 두고, glTF가 이런 것을 푸는 방식을 FBX에 옮겼습니다.

- **회전이 Blender 그대로 들어옵니다.** 내보낼 때 아무것도 돌리지 않고 파일에 "Blender의 축"이라고만 적고, Unity가 가져올 때 축 변환을 데이터에 굽습니다(`bakeAxisConversion`). 깊은 계층, 키프레임으로 움직이는 오브젝트, 스킨 메시, 본에 매단 오브젝트까지 부품 자세가 Blender와 같습니다. 본 끝의 `_end` 본도 붙지 않습니다.
- **재질이 이 프로젝트의 재질로 만들어집니다.** Blender가 각 재질의 Principled BSDF가 읽는 값과 이미지(기본 색, 금속, 거칠기, 노멀, 발광, 투명도)를 모델 옆에 적어 보내고, Unity가 그것으로 URP Lit(렌더 파이프라인이 없으면 Standard) 재질을 모델 옆 `Materials/`에, 이미지를 `Textures/`에 만듭니다. .blend에 팩된 이미지와 저장한 적 없는 이미지도 갑니다. Unity에서 고친 재질은 다시 보낼 때 덮어쓰지 않습니다.
- **노드로 만든 재질은 텍스처로 구워 보냅니다.** 이미지나 값을 곧바로 읽지 않고 다른 노드를 거치는 입력(노이즈, 컬러 램프, 범프 등)은 Blender가 그 입력만 이미지로 구워(기본 1024×1024) 다른 이미지처럼 보냅니다. 기본 색, 금속, 거칠기, 노멀, 발광 색이 됩니다. 한 장에 0.2~1초쯤 걸리고, 선택과 재질의 노드는 그대로입니다. 구운 이미지는 그때의 노드 모습이라 Unity에서는 더는 노드처럼 움직이거나 바뀌지 않습니다. 무엇을 구웠는지는 결과의 `baked`에 적힙니다. UV 맵이 없는 메시는 굽지 못하고, 편집 모드에서 보내거나 저장하면 그 번에는 굽지 않고(Unity에 먼저 구운 이미지가 있으면 그것이 그대로 쓰입니다) 오브젝트 모드에서 다시 굽습니다.
- **옮기지 못한 것은 말해 줍니다.** 굽지 못한 입력, Principled BSDF가 아닌 셰이더, 노드를 거친 투명도와 발광 세기는 어느 재질의 무엇인지 결과에 적힙니다(`not_carried`).
- **보낸 것과 같은지 Unity가 재어 봅니다.** Blender가 보내기 전에 오브젝트마다 자리와 메시가 닿는 범위를 재어 같이 보내고, Unity가 가져온 모델에서 같은 것을 재어 견줍니다(결과의 `shape_check`). 돌아갔거나 옮겨졌거나 크기가 다르거나 빠진 부품이 있으면 어느 부품인지 알려 줍니다. 저장을 따라가는 모델이 다르게 들어가면 Blender 패널에도 한 줄이 뜹니다. 리그나 셰이프 키로 모양이 바뀌는 메시는 자리만 봅니다.
- **액션 없이 움직이는 것도 옵니다.** 강체처럼 물리로만 움직이는 오브젝트, 셰이프 키만 움직이는 오브젝트, 여러 오브젝트가 함께 움직이는 장면은 장면의 프레임 범위가 클립 하나로 갑니다. 리그 하나에 액션이 여럿이면 액션마다 클립 하나가 그 액션의 이름으로 갑니다.
- **지오메트리 노드의 인스턴스가 메시로 옵니다.** 내보내는 동안에만 실체화합니다.
- **씬에 놓으면 움직입니다.** 클립이 있는 모델을 처음 놓을 때 Animator와, 클립마다 상태가 있는 Animator Controller가 붙습니다.
- **Humanoid.** `ch_import_model`의 `rig="humanoid"`(Blender 쪽은 `export_fbx(..., humanoid=True)`)로 Unity의 Humanoid로 받습니다. Unity가 본을 사람으로 맞추지 못하면 Generic으로 받고 그렇게 알려 줍니다.

Unity 6000.3(URP)과 Blender 5.2에서 창 없이 확인했습니다. 0.16.0까지 보낸 모델은 다음에 다시 보낼 때 새 방식으로 바뀌고, 그때 모델 안 부품들의 회전 값이 달라집니다(보이는 모양은 같습니다).

2026-11-24에 열린 Unity(hand_test)와 열린 Blender에서 Claude 없이 되는 것(패널에서 보내기, 저장 따라가기, 굽기, 되돌리기)을 실제로 돌려 보았고, 창 없이는 드러나지 않던 다섯 가지를 고쳤습니다.

- **모양 검사가 섭디비전 메시를 "다르게 들어갔다"고 했습니다.** 열린 창에서는 Blender가 알려 주는 경계 상자가 섭디비전 전 크기였습니다. 이제 내보내는 메시(모디파이어 적용)에서 직접 잽니다.
- **굽지 못하고 미룬 것까지 "구워 보냈어요"라고 했습니다.** 편집 모드라 미룬 굽기는 이제 `baked`에 넣지 않고, 저장을 따라가는 모델이면 패널에 "오브젝트 모드에서 저장하면 구워서 갑니다" 한 줄이 뜹니다.
- **Unity에서 고친 재질을 지킨 것을 Blender에서는 알 수 없었습니다.** Blender에서 재질을 바꿔 저장했는데 Unity가 그대로라 안 간 것처럼 보였습니다. 이제 패널에 어느 재질을 Unity 것 그대로 뒀는지와, 다시 만들려면 그 .mat을 지우라는 줄이 뜹니다(`ch_model_follow update`의 결과에 `materials_made`).
- **저장으로 한 번 다시 들어온 모델을 되돌리면 폴더가 남았습니다.** 움직임이 있는 모델(Animator Controller가 같이 만들어짐)을 Unity 채팅창의 되돌리기로 뺄 때, Unity가 컨트롤러 파일을 잠깐 열어 두어 폴더를 옮기지 못했습니다("Access denied"). 옮기기 전에 Unity가 쥔 파일을 놓게 합니다(`AssetDatabase.ReleaseCachedFileHandles`).
- **다른 모델의 재질 · 메시를 고쳐도 모든 모델이 건드려진 것으로 쳤습니다.** 그래서 Bevel이 붙은 모델이 상관없는 저장마다 다시 갔고, 무거운 모델은 쓸데없이 내보내졌습니다. 이제 바뀐 메시 · 재질을 쓰는 모델만 건드려진 것으로 칩니다.

같은 날 실제 감독 세션으로 27~31단계를 보다가 셋을 더 고쳤습니다.

## 0.14.0 (2026-11-23): 여러 창을 한 번에 되돌리기

Blender 채팅창에서 시킨 "고쳐서 Unity로 보내줘"는 Blender와 Unity를 함께 바꿉니다. 되돌리기는 창마다 따로였고, 요청한 채팅창의 버튼이 그 요청과 상관없는 앞 요청을 가리키기도 했습니다.

- **요청한 채팅창의 되돌리기 버튼이 그 요청이 바꾼 다른 창까지 되돌립니다.** 버튼에 "되돌리기: 요청 글 (이 창 + hand_test (Unity))"처럼 어디가 돌아가는지 적혀 있습니다. 결과는 창마다 한 줄로 채팅창에 오고, 되돌아간 창의 채팅창에도 한 줄 남습니다.
- **창마다 그 요청이 가장 새 변경일 때만 되돌립니다.** 그 뒤에 다른 요청이 그 창을 바꿨거나 그 창이 작업 중이면 건너뛰고 이유를 알려 줍니다. 풀린 뒤 같은 버튼을 다시 누르면 남은 창만 되돌립니다.
- **"방금 거 취소해줘"도 같은 길로 갑니다.** 감독이 하위 세션에게 맡기지 않고 채널의 `undo_request` 도구를 부릅니다. 전에는 하위 세션이 자기 창의 가장 최근 요청을 되돌려서, 취소하려던 요청이 아닐 수 있었고 다른 창은 남았습니다. 이 도구는 실행 전에 채팅창에 허용·거부 버튼이 뜹니다.
- **한 창에는 한 번에 한 요청의 일만 맡깁니다.** 그 창이 다른 요청으로 일하는 중이면 맡기는 호출이 거부되고, 감독은 앞 일이 끝난 뒤 맡깁니다. 전에는 뒤 요청이 앞 일의 기록, 되돌리기 지점, 중지를 가져갔습니다.
- 자동 테스트와 창 없이 연 Unity·Blender에서 확인했습니다. 열린 창과 실제 감독 세션으로 하는 확인은 [TEST-PLAN](TEST-PLAN.md) 28단계에 남아 있습니다.

## 0.12.1 (2026-11-12): 실제 감독 세션에서 찾은 것 고침

며칠째 이어 쓰는 실제 감독 세션에 채팅창처럼 요청을 넣어 보고 찾은 것들입니다. 미리보기 그림은 한 번도 섞이지 않았습니다.

- **되돌리기 지점은 요청마다, 창마다 하나입니다.** 무언가를 바꾸는 첫 동작 앞에 찍히고, 이름은 그 일을 시킨 채팅창의 글입니다. 하위 세션이 지점을 따로 찍거나, 일하는 중에 온 답 때문에 지점이 둘이 되던 것을 막았습니다.
- **되돌리기로 뺀 에셋은 `Library/ClaudeHand/removed`에 보관합니다.** 전에는 Windows 휴지통으로 보냈는데, 휴지통이 "바로 삭제"로 설정된 PC에서는 그대로 사라졌습니다.
- **Claude Hand를 다시 켠 뒤의 첫 요청에도 요청 번호가 이어집니다.** 감독이 예전 하위 세션을 이어 부르면, 방금 켠 채널은 그것이 그 창의 하위 세션인 줄 몰랐습니다.
- **"하는 중" 답 뒤에 누른 중지도 그 요청의 것입니다.** 그 요청으로 일하던 다른 창까지 막고, `trace`에 `중지 누름`으로 남습니다. 중지의 답이 오면 일하던 창이 바로 풀립니다(전에는 5분 동안 `작업 중`으로 남았습니다).
- **다른 창 줄이 맞게 보입니다.** 일을 맡긴 뒤부터 결과가 올 때까지 `답 기다림`입니다(전에는 사이사이 `한가함`이었습니다). 다른 창의 요청으로 일한 창의 작업 줄은 그 일이 끝나면 바로 사라집니다.
- **감독의 답은 일이 계속되는지를 꼭 밝힙니다(`working`).** 빠진 답은 채널이 돌려보내 다시 쓰게 합니다. 작업 줄, 중지 버튼, 답이 왔다는 알림이 이 값에 달려 있습니다.
- 들여다보기만 한 창의 그림은 답에 붙지 않습니다.

## 0.12.0 (2026-11-11): 창들의 현황 한눈에

- 채팅창 입력칸 위에 **다른 창** 줄이 생겼습니다. 다른 창이 `작업 중`인지(누구의 요청인지), `답 기다림`인지, `대화상자로 멈춤`인지 한 줄씩 보입니다.
- `claude_hand.py status`가 같은 내용을 경과 시간, 지금 하는 동작과 함께 명령줄에 보여 줍니다.
- 감독도 "지금 다들 뭐 해?"라는 물음에 이 상태로 답합니다.

## 0.11.0 (2026-11-11): 파일까지 되돌리기

- Unity의 **되돌리기**가 그 요청이 파일에 한 일도 돌립니다. 다시 보낸 모델로 바뀐 파일은 이전 것으로 돌아가고(GUID와 가져오기 설정 그대로), 새로 들어온 모델과 패키지 에셋은 프로젝트에서 빠집니다.
- 채팅창의 확인 창과 안내가, 파일 몇 개가 돌아가고 에셋 몇 개가 빠지는지 알려 줍니다.
- 프로젝트 사이 옮기기(`ch_export_objects`, `ch_import_package`)가 Unity 자체 테스트에 들어갔습니다.

## 0.10.0 (2026-11-11): 요청 번호 잇기

- 감독이 하위 세션에게 일을 맡길 때 어느 채팅창 요청의 일인지(`[요청 <번호>]`) 적고, 감독 세션의 훅(`tools/supervisor_hook.py`)이 그것을 채널에 알립니다. 번호가 빠진 맡기기는 거부되고, 적는 법을 안내받습니다.
- 그래서 채널이 추측하던 것이 정확해졌습니다: 미리보기 그림이 붙을 채팅창, 중지가 미치는 창, `trace`의 요청 번호(`맡김` 줄), 되돌리기 버튼의 이름.

## 0.9.1 (2026-11-11): 미리보기 그림이 다른 채팅창에 붙던 문제

- Unity 프로젝트 둘을 나란히 쓸 때 서로의 그림이 붙던 문제를 고쳤습니다. 감독이 답할 때 그 요청으로 바뀐 창을 적고, 일이 보이기 전에 온 "하는 중" 답은 결과로 치지 않습니다.
- 같은 모델을 1초 안에 두 번 바꿔도 바꾸기 전 파일이 모두 남습니다.
- `materials="embedded"`로 프로젝트 머티리얼 연결을 풀면, 어느 연결이 풀렸는지 답에 나옵니다.

## 0.9.0 (2026-11-10, 태그 `v0.9.0`): 모델 다시 보내기, 요청 기록, 중지

- **다시 보낸 모델은 제자리에서 바뀝니다.** 같은 .blend의 같은 오브젝트를 다시 보내면 Unity가 새로 넣지 않고 있던 모델 파일을 바꿉니다. `materials="project"`로 프로젝트의 머티리얼에 연결할 수 있습니다.
- **Unity → Blender로 보낼 수 있습니다**(`ch_export_model`, 애드온의 `import_model`). 이것으로 네 방향이 다 됩니다.
- **요청 기록**: 요청마다 번호가 붙고 그 뒤의 일이 파일에 남습니다. `claude_hand.py trace`로 봅니다.
- **중지 버튼**: 채팅창의 작업 줄 옆에서, 그 요청의 다음 동작부터 막습니다.
- Unity 도구를 창 없이 연 Unity에서 실제로 돌려 보는 자체 테스트가 생겼습니다(`selftest --unity-project`).
- MIT 라이선스를 붙였습니다.

## 0.8.0 (2026-11-10): 구조 개편

[구조 점검](REVIEW-2026-11-10.md)에서 나온 것을 고쳤습니다.

- 버전을 `VERSION` 한 곳에서 정합니다. 전에는 서버, Unity 패키지, Blender 애드온의 번호가 따로였습니다.
- 안전장치를 작은 파일 하나(`tools/guard.py`)로 떼어, 다른 파일의 오류가 안전장치를 끄지 못하게 했습니다.
- Unity 패키지가 MCP for Unity 없이도 컴파일됩니다.
- `claude_hand.py`를 모듈로 나누고(`tools/handlib/`), Claude에게 주는 지침을 파일로 뺐습니다(`prompts/`).
- 감독이 지킬 규칙 가운데 채널이 알 수 있는 것은 코드로 지킵니다. 같은 창에 하위 세션 둘이 붙으면 막고, 일이 끝났는데 답이 없으면 감독에게 다시 알립니다.
- Blender의 옮기기(`export_blend`, `import_blend`, `export_fbx`)가 애드온의 함수가 됐습니다.
- `unity-install`이 릴리스 태그를 받은 체크아웃에서는 GitHub 주소로, 아니면 폴더 경로로 패키지를 넣습니다.
- 교환 폴더의 옮긴 파일을 30일 뒤에 정리합니다. GitHub에서 테스트가 Windows와 Linux에서 돕니다.
