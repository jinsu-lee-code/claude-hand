## Order of work: snapshot → ref → act → check
1. Look at the scene with `ch_scene_snapshot` and pick the target's ref (of the form `@s1a2b3c4:e5`). If the scene is large, lower `depth` and dig in with `root=<ref>`.
2. Pass refs to the `ch_*` tools, and a node's `path` or `instance_id` to MCP for Unity's own tools.
3. After changing something, take the snapshot again and check the result. If `STALE_REF` comes, use the refs of the new snapshot.
4. When an error's `retry` is `safe`, do it again as it is; when `after_fix`, with the arguments corrected; when `check_first`, check the state first and then do it again.
5. When a `ch_*` tool says it "does not answer", see why with `ch_bridge_status`. If Unity is reloading scripts, do it again a few seconds later; if the project is closed or Claude Hand Tools has not compiled, report to the supervisor.
6. When an MCP for Unity tool fails with `No Unity Editor instances found`, `Could not connect to Unity` or `Unity is reloading`, this project's Unity is not answering for a moment (reloading scripts, a large import, closed). Do it again a few seconds later, and if it is still so after about three tries, report to the supervisor what was done and what is left. If `mcp_for_unity.running` of `ch_editor_status` is false, the connection is off, and Claude Hand Tools turns it back on after about 20 seconds. This server sees only this project's Unity. Do not go around it to call another project.

## Exchanging objects with another project
- To send: check the refs with a snapshot → `ch_export_objects(refs=[...], name="...")` → hand the `manifest_path` of the result back to the supervisor as it is.
- To receive: check first with `ch_import_package(manifest=..., dry_run=true)`. If there is even one of `would_overwrite`, `same_guid_elsewhere`, `missing_packages`, `warnings`, stop and report it to the supervisor as it is. If there is no problem, run it without `dry_run` and report the `placed` refs of the result.
- To receive a model Blender sent (a `claude-hand/model@1` manifest, FBX): `ch_import_model(manifest=...)`. Report the `placed` refs and the `warnings` of the result.
  - The materials are made as materials of this project, as the manifest describes them, and put next to the model in `Materials/`, `Textures/` (the `materials_made` of the result). If the `not_carried` of the result has text, those are material inputs that could not be brought over from Blender: report them as they are. What is in `baked` are inputs whose nodes came baked to a texture (an image fixed as it looked at that moment). Materials changed in this project are not overwritten when the model is received again (they show in `warnings`).
  - The `shape_check` of the result says whether the imported model has the same places · sizes as Blender measured. If `same` is false, report `differing` (parts placed differently or of a different size) and `missing` (parts that did not come) as they are. Do not just pass over it.
  - If told to receive a human rig as Humanoid, `rig="humanoid"`. If it could not be matched and was received as Generic, that shows in `warnings`: report it as it is.
  - When the same object of the same .blend comes again, it is not added anew: the model file the project had is replaced in place (the `updated` of the result is true). What is placed in scenes and prefabs takes the new shape where it stands. Report `asset_path`, `instance_count`, `instances`. This file replacement too is taken back by undoing (the file from before the replacement is put back). Report `previous_file` (where the file from before the replacement is kept) as well.
  - Use `new_copy=true` only when told that a separate second copy is needed.
  - If there is a request, or a rule of this project, to use the project's materials of the same name, put in `materials="project"`. From the `materials` of the result, report `linked` (linked), `unmatched` (not in the project, so the model's own is used), `ambiguous` (two or more of the same name, so left as it is). If the request is to go back to the materials inside the model, put in `materials="embedded"` and report the `unlinked` of the result (links released).
- A request to have a model change along with every save in Blender (`ch_model_follow`): find that model's `asset_path` with `ch_model_follow(action="list")` and turn it on with `ch_model_follow(action="set", asset_path="Assets/...", follow=true)`.
